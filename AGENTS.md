# AGENTS.md — NetHack 5.0.0

Guidance for AI coding agents working in this repository.

## What this is

The NetHack 5.0.0 source tree: a single-user, turn-based dungeon exploration
game written in C (C99), descended from NetHack 3.6. It is a mature,
cross-platform codebase — the same core builds for Unix, macOS, Windows, and
MS-DOS, with multiple windowing interfaces. Data files (levels, dungeon
layout, monsters, objects) are Lua-based and compiled/loaded at run time,
not generated by yacc/lex tools as in 3.6.

## Repository layout

| Path | Contents |
|---|---|
| `src/` | Core game engine C sources (one file per major subsystem: `eat.c`, `dig.c`, `do_wear.c`, ...) |
| `include/` | Headers shared across the tree (`hack.h` is the central one) |
| `dat/` | Game data: dungeon/level definitions in Lua (`dungeon.lua`, `<Role>-strt.lua`, ...), text data files |
| `util/` | Build-time utilities: `makedefs`, `dlb_main` (data librarian), `recover` |
| `sys/` | Platform support. `sys/unix/` holds the Unix build (hints files, setup script, Makefile fragments); `sys/winnt/`, `sys/msdos/`, etc. for other platforms |
| `win/` | Windowing interfaces: `tty/`, `curses/`, `X11/`, `win32/`, `Qt/` |
| `sound/` | Sound support (per-platform) |
| `submodules/` | Git submodules: `lua`, `pdcurses`, `pdcursesmod` |
| `doc/` | Player and developer docs; `fixes5-0-0.txt` is the changelog |
| `test/` | Lua test scripts run in-game via wizmode `wizloadlua` (requires a build without DLB) |
| `DEVEL/` | Developer tooling: `code_style.txt`, `Developer.txt`, git hooks (`nhgitset.pl`), `git_recipes.txt` |
| `outdated/` | Superseded material kept for reference — do not edit |

## Building (Unix)

Configure and build from the top directory:

```sh
cd sys/unix
sh setup.sh hints/linux.500      # pick the hints file matching your platform
cd ../..
make fetch-Lua                   # one time; downloads/unpacks Lua into lib/ (needs network)
make all
```

- `make spotless` cleans all generated files before retrying a failed build.
- `make install` **deletes and recreates** the playground (nethackdir) —
  save `record`, `logfile`, and `sysconf` first if you need them.
- Windowing interfaces are opt-in via make variables:
  - `make WANT_WIN_TTY=1 WANT_WIN_CURSES=1 all` (tty + curses)
  - `make WANT_WIN_ALL=1 all` (tty + curses + X11 + Qt on Unix)
- Other platforms: see `sys/winnt/`, `sys/mac/`, `Cross-compiling` (top level).

## Conventions

- **Language standard:** C99. Follow `DEVEL/code_style.txt`; the repo also has
  a top-level `.clang-format`.
- **NHDT tags:** nearly every source file carries
  `$NHDT-Date: ... $ $NHDT-Branch: ... $:$NHDT-Revision: ... $` version-stamp
  comments, maintained by the git hooks in `DEVEL/`. Do not hand-edit or strip
  them. Run `DEVEL/nhgitset.pl` if hooks are not installed.
- **Commit messages:** subject ≤ 50 chars, blank line before an optional body
  wrapped at 72 chars (see `Contributing.md`).
- **Files to not touch casually:** generated files listed in `dat/GENFILES`,
  `Files` (the authoritative file manifest — update it if you add/remove
  shipped files), and everything under `outdated/`.

## Testing

There is no standalone unit-test suite. Validation is done by:

1. Building cleanly (warnings in this codebase are meaningful — keep the
   build warning-free for your change).
2. Running the game (`make install` then the `nethack` launcher) and
   exercising the changed code paths.
3. Optionally running the Lua test scripts in `test/` inside a wizard-mode
   game via the `wizloadlua` extended command — requires a build compiled
   **without** DLB (`#define DLB` removed) and the test files copied into the
   playground directory. See `test/README.md`.

## Gotchas

- The build is configured *in place* by `setup.sh` (it generates top-level
  Makefiles and `include/config.h` from the hints file). Changing platform or
  options usually means `make spotless` and re-running `setup.sh`.
- Game data lives in Lua files under `dat/` with a specific schema — study an
  existing example (e.g. a small level like `knox.lua`) before writing a new one.
- `include/hack.h` and friends are included nearly everywhere; changes to
  shared headers trigger full rebuilds and can have wide behavioral impact.
